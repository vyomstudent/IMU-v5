VSPIMU V5.8 FINAL PACKAGE — QA-CLEAN BUILD
=============================================

SOURCE BASIS
- Last known working v5_gait(6) architecture, preserving window.VSPIMU and the existing STOP/report flow.
- Existing verified TCN header/model; no model weights regenerated and no parity tolerance loosened.

FIXES INCLUDED
- TCN workspace: 12,864 bytes; header allocator order PSRAM -> IRAM_8BIT -> internal 8-bit -> host malloc.
- Three TCN feature/output buffers are independently allocated by the firmware wrapper.
- Baseline warmup is time-bounded and accepts >= 1,872 successful samples out of 2,080.
- Exact raw packet remains 192 bytes; original BLE identity/service/data/cmd UUIDs remain unchanged.
- Analytics characteristic uses v5/type1 168-byte summary and v5/type2 144-byte event chunks.
- Raw CRC32 is computed over the exact integer stream before scaling.
- ESP32 and phone compute independently; parity only compares them after finalization.
- Final parity result is rendered at the bottom of the HTML near the model/debug section and is also included in report Section 6A.
- window.IMU is a compatibility alias to window.VSPIMU.
- Removed duplicate firmware detectorThresholds() definition.
- Added all DOM IDs used by the final JS and corrected stale V5.7.1 dashboard wording.
- Added esp_heap_caps.h conditionally inside gait_tcn_model.h for self-contained ESP32 compilation.
