============================================================
2 — BluetoothLE1.Connected
============================================================

When BluetoothLE1.Connected fires:

  set global BLE_READY to true
  set global ANALYTICS_REGISTERED to false
  set global PARITY_VERDICT to "NOT READY"

  call WebViewer1.RunJavaScript
    "window.VSPIMU.bleConnected();"

  call BluetoothLE1.RequestMTU
    bytes = 247

  call BluetoothLE1.RegisterForShorts
    serviceUuid = 7b8a0001-4f2a-4a2e-9e51-1d9b6d8d5001
    characteristicUuid = 7b8a0002-4f2a-4a2e-9e51-1d9b6d8d5001
    signed = true

  call BluetoothLE1.RegisterForBytes
    serviceUuid = 7b8a0001-4f2a-4a2e-9e51-1d9b6d8d5001
    characteristicUuid = 7b8a0004-4f2a-4a2e-9e51-1d9b6d8d5001
    signed = false

  set global ANALYTICS_REGISTERED to true

IMPORTANT:
  Do NOT register DATA or ANALYTICS again in MTUChanged.
  Connected is now the only subscription registration point.

The ESP32 firmware will not begin sampling until the negotiated client
MTU is at least 195 bytes, so registering the raw stream before MTU change
is safe: no 192-byte DATA packet is sent before the MTU is large enough.

============================================================
3 — BluetoothLE1.MTUChanged
============================================================

Keep this event only for status/readiness information.

Do NOT call RegisterForShorts here.
Do NOT call RegisterForBytes here.

Example:
  when BluetoothLE1.MTUChanged bytes
      if bytes >= 195
          set global BLE_READY to true

No second registration is allowed.

5 — BluetoothLE1.BytesReceived
============================================================

Create/use:

when BluetoothLE1.BytesReceived
    serviceUuid
    characteristicUuid
    byteValues

Filter BOTH UUIDs:

  if downcase(serviceUuid)
      = "7b8a0001-4f2a-4a2e-9e51-1d9b6d8d5001"
  AND
     downcase(characteristicUuid)
      = "7b8a0004-4f2a-4a2e-9e51-1d9b6d8d5001"
  then

      call WebViewer1.RunJavaScript
        script =
          join(
            "window.VSPIMU.receiveEspAnalyticsCsv(\"",
            call list to CSV row byteValues,
            "\");"
          )

DO NOT set LabelStatus.Text inside BytesReceived.
DO NOT write any "ESP analytics RX ... packet N" diagnostic to LabelStatus.
The BytesReceived event is transport-only.

Do NOT convert the bytes to JSON.
Do NOT manually decode the 168/144 byte packet in App Inventor.
Do NOT send analytics through WebViewString.

Expected packet sizes:
  summary = 168 bytes
  event   = 144 bytes

6 — START BUTTON
============================================================

Use the existing START command.

When ButtonStart.Click:

  call WebViewer1.RunJavaScript
    "window.VSPIMU.start();"

  call BluetoothLE1.WriteStrings
    serviceUuid = SERVICE_UUID
    characteristicUuid = CMD_UUID
    values = make a list of "START"

Do NOT block the START command on MTUChanged.
Do NOT create a second START command.
Do NOT wait for a packet called 168B before START.

The ESP32 itself queues START until its negotiated MTU is >=195 and any
previous finalization/storage work has completed.

8 — WebViewStringChange
============================================================

Keep the existing JSON status handling.

After decoding a JSON dictionary, add:

  if lookup key "type" = "ESP_PARITY_RESULT"
  then
      set global PARITY_VERDICT to lookup key "verdict"
      set LabelStatus.Text to
        join(
          "ESP32↔APP PARITY ",
          global PARITY_VERDICT
        )

  else if lookup key "type" = "status"
  then
      if global PARITY_VERDICT = "NOT READY"
      then
          set LabelStatus.Text to join(lookup key "status", " | ", lookup key "detail")

  else if lookup key "type" = "ESP_ANALYTICS_ERROR"
  then
      set LabelStatus.Text to "ESP analytics transport/decode error"

Possible final values:
  ESP32↔APP PARITY PASS
  ESP32↔APP PARITY WARN
  ESP32↔APP PARITY FAIL

No parity packet data should travel through WebViewString.

10 — REQUIRED FINAL FLOW
============================================================

CONNECT
  -> WebViewer1.RunJavaScript("window.VSPIMU.bleConnected();")
  -> RequestMTU(247)
  -> RegisterForShorts(DATA_UUID)
  -> RegisterForBytes(ANALYTICS_UUID)

START
  -> RunJavaScript("window.VSPIMU.start();")
  -> WriteStrings(CMD_UUID,"START")

DURING JOURNEY
  DATA_UUID -> ShortsReceived -> phone analytics
  ANALYTICS_UUID -> NO periodic analytics packets

STOP
  -> WriteStrings(CMD_UUID,"STOP")
  -> RunJavaScript("window.VSPIMU.stop();")

FINALIZATION
  ESP32 performs Stage 1/4 -> Stage 4/4

PARITY
  ESP32 sends final 168-byte summary
  ESP32 sends final IC 144-byte packet(s)
  ESP32 sends final FC 144-byte packet(s)
  ESP32 sends final summary again
  JS receives packets through receiveEspAnalyticsCsv()
  JS computes PASS/WARN/FAIL
