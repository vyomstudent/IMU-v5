VSPIMU V6 DUAL-IMU — MIT APP INVENTOR INTEGRATION BLOCKS
Version: 1.0.0

PURPOSE
-------
Add optional Android phone accelerometer/gyroscope capture to the existing working
VSPIMU app. Do NOT replace the BLE parser, VSPIMU.start(), VSPIMU.stop(), existing
TCN/Wavelet/AFO code, report viewer, tf.min.js, model.json or its weight shards.

IMPORTANT LIMITATION
-------------------
MIT App Inventor's AccelerometerSensor.AccelerationChanged event does not provide
Android SensorEvent.timestamp. Its timestamp below is Clock.SystemTime at callback.
GyroscopeSensor.GyroscopeChanged does provide its native nanosecond timestamp.
Therefore phone gyro intervals are timestamped more precisely than phone acceleration;
phone-to-shank alignment remains exploratory, not guaranteed millisecond synchronization.
Motion sensors do not normally require a dangerous runtime Android permission. The
user-facing checkbox is the explicit opt-in; .Available is checked for absent sensors.

4. PROCEDURE: SendPhoneSensorStatus
-----------------------------------
Set these four TEXT globals to literal lowercase JavaScript booleans:
  PHONE_ACC_AVAILABLE_TEXT = if AccelerometerSensor1.Available then "true" else "false"
  PHONE_GYRO_AVAILABLE_TEXT = if GyroscopeSensor1.Available then "true" else "false"
  PHONE_ACC_ENABLED_TEXT = if AccelerometerSensor1.Enabled then "true" else "false"
  PHONE_GYRO_ENABLED_TEXT = if GyroscopeSensor1.Enabled then "true" else "false"

Call WebViewer1.RunJavaScript with this joined text:
  "window.VSPIMUPhoneIMU.setNativeSensorStatus("
  + PHONE_ACC_AVAILABLE_TEXT + ","
  + PHONE_GYRO_AVAILABLE_TEXT + ","
  + PHONE_ACC_ENABLED_TEXT + ","
  + PHONE_GYRO_ENABLED_TEXT + ");"

The JavaScript boolean arguments must be true/false, not quoted text.

5. PROCEDURE: FlushPhoneIMUQueue
--------------------------------
1) Set global PHONE_IMU_BATCH to global PHONE_IMU_QUEUE.
2) Set global PHONE_IMU_QUEUE to a new empty list immediately.
3) If length of global PHONE_IMU_BATCH > 0:
   call WebViewer1.RunJavaScript with:
      join(
        "window.VSPIMUPhoneIMU.ingestBatch(",
        call Web1.JsonObjectEncode(global PHONE_IMU_BATCH),
        ");"
      )
4) Set global PHONE_IMU_BATCH to a new empty list.
5) If PHONE_IMU_DROPPED_ROWS > PHONE_IMU_DROPPED_ROWS_REPORTED, call:
     WebViewer1.RunJavaScript(
       join("window.VSPIMUPhoneIMU.recordLifecycleEvent(\"native_queue_overflow_interruption_dropped_",
            PHONE_IMU_DROPPED_ROWS, "\");")
     )
   Then set PHONE_IMU_DROPPED_ROWS_REPORTED to PHONE_IMU_DROPPED_ROWS.
   This makes an overflow visible as an interrupted/REVIEW session; do not silently
   treat a queue-overflowed stream as complete.

Use JsonObjectEncode so special characters/values are encoded as JSON. Do not build the
JavaScript array by joining unescaped sensor values. The batch size depends on the event rate actually delivered by Android; do not interpret
the 100-ms queue flush interval as the sensor sampling interval.

6. SENSOR EVENT BLOCKS
----------------------
when AccelerometerSensor1.AccelerationChanged(xAccel, yAccel, zAccel):
  if global PHONE_CAPTURE_ENABLED is true:
    if length(global PHONE_IMU_QUEUE) < global PHONE_IMU_QUEUE_CAP:
      add items to list global PHONE_IMU_QUEUE:
        make a list
          "acc"
          call ClockPhoneFlush.SystemTime
          0
          xAccel
          yAccel
          zAccel
    else:
      set global PHONE_IMU_DROPPED_ROWS to global PHONE_IMU_DROPPED_ROWS + 1

Values are in m/s^2 and include the measured device-frame gravity/specific-force
convention of the component. The event's timestamp is callback wall-time; no native
sensor timestamp is available from this component's event signature.

when GyroscopeSensor1.GyroscopeChanged(xAngularVelocity, yAngularVelocity,
                                         zAngularVelocity, timestamp):
  if global PHONE_CAPTURE_ENABLED is true:
    if length(global PHONE_IMU_QUEUE) < global PHONE_IMU_QUEUE_CAP:
      add items to list global PHONE_IMU_QUEUE:
        make a list
          "gyro"
          call ClockPhoneFlush.SystemTime
          timestamp
          xAngularVelocity
          yAngularVelocity
          zAngularVelocity
    else:
      set global PHONE_IMU_DROPPED_ROWS to global PHONE_IMU_DROPPED_ROWS + 1

Gyroscope velocities are in degrees/second; timestamp is nanoseconds per AI2 docs.

when ClockPhoneFlush.Timer:

8. WEBVIEW STRING MESSAGE HANDLER
---------------------------------
Extend the EXISTING WebViewer1.WebViewStringChange(value) event. Keep the current status
message path. Add these branches BEFORE the old plain-text fallback. All payloads are
JSON with "type" as the first property (the JavaScript uses JSON.stringify in that order).

BRANCH A — value starts with {"type":"phone_imu_control"
  set local/global D = call Web1.JsonTextDecode(value)
  set COMMAND = lookup key "command" in dictionary D
  set REQUESTED = lookup key "requested" in dictionary D

  If COMMAND = "START":
    set global PHONE_CAPTURE_REQUESTED = true
    set AccelerometerSensor1.Enabled = AccelerometerSensor1.Available
    set GyroscopeSensor1.Enabled = GyroscopeSensor1.Available
    set global PHONE_CAPTURE_ENABLED =
      (AccelerometerSensor1.Enabled OR GyroscopeSensor1.Enabled)
    set ClockPhoneFlush.TimerEnabled = global PHONE_CAPTURE_ENABLED
    call SendPhoneSensorStatus
    If neither sensor Available:
      set LabelStatus.Text = "Phone motion sensors unavailable; shank-only capture continues."

  If COMMAND = "STOP":
    call FlushPhoneIMUQueue FIRST (the JS module accepts this queued stop-tail batch)
    set global PHONE_CAPTURE_REQUESTED = false
    set global PHONE_CAPTURE_ENABLED = false
    set ClockPhoneFlush.TimerEnabled = false
    set AccelerometerSensor1.Enabled = false
    set GyroscopeSensor1.Enabled = false
    call SendPhoneSensorStatus

BRANCH B — value starts with {"type":"phone_imu_export_begin"
  Decode D. Set the globals from keys:
    exportId -> PHONE_EXPORT_ID
    filename -> PHONE_EXPORT_FILENAME
    totalChunks -> PHONE_EXPORT_TOTAL_CHUNKS
    totalChars -> PHONE_EXPORT_TOTAL_CHARS
  Set PHONE_EXPORT_NEXT_INDEX = 0
  Set PHONE_EXPORT_RECEIVED_CHARS = 0
  Set PHONE_EXPORT_IS_SAVING = false
  Set PHONE_EXPORT_FINISH_PENDING = false
  Call WebViewer1.RunJavaScript:
    join("window.VSPIMUPhoneIMU.ackExportBegin(\"", PHONE_EXPORT_ID, "\");")

BRANCH C — value starts with {"type":"phone_imu_export_chunk"
  Decode D. Read exportId, filename, index and text.
  Only accept the chunk when:
    exportId = PHONE_EXPORT_ID
    index = PHONE_EXPORT_NEXT_INDEX
    PHONE_EXPORT_IS_SAVING = false
  Store:
    PHONE_EXPORT_PENDING_ID = exportId
    PHONE_EXPORT_PENDING_INDEX = index
    PHONE_EXPORT_PENDING_CHARS = length(text)
    PHONE_EXPORT_IS_SAVING = true
  If index = 0:
    call FilePhoneExport.SaveFile(text, PHONE_EXPORT_FILENAME)
  Else:
    call FilePhoneExport.AppendToFile(text, PHONE_EXPORT_FILENAME)

BRANCH D — value starts with {"type":"phone_imu_export_done"
  Decode D. Check:
    exportId = PHONE_EXPORT_ID
    PHONE_EXPORT_NEXT_INDEX = PHONE_EXPORT_TOTAL_CHUNKS
    PHONE_EXPORT_RECEIVED_CHARS = PHONE_EXPORT_TOTAL_CHARS
    PHONE_EXPORT_IS_SAVING = false
  If every check passes:
    call Sharing1.ShareFile(PHONE_EXPORT_FILENAME)
    call WebViewer1.RunJavaScript:
      join("window.VSPIMUPhoneIMU.ackExportComplete(\"", PHONE_EXPORT_ID,
           "\",true,\"saved\");")
  Else:
    call WebViewer1.RunJavaScript:
      join("window.VSPIMUPhoneIMU.ackExportComplete(\"", PHONE_EXPORT_ID,
           "\",false,\"chunk/length mismatch\");")
  Reset PHONE_EXPORT_ID and PHONE_EXPORT_FILENAME after ShareFile is invoked.

BRANCH E — existing status JSON starts with {"type":"status"
  KEEP the existing status handler that decodes "status" and "detail" into LabelStatus.

ELSE:
  Keep the existing fallback display for plain-text status messages.

8A. FILEPHONEEXPORT.AFTERFILESAVED(filename)
--------------------------------------------
If PHONE_EXPORT_IS_SAVING is true and filename = PHONE_EXPORT_FILENAME:
  set PHONE_EXPORT_RECEIVED_CHARS =
      PHONE_EXPORT_RECEIVED_CHARS + PHONE_EXPORT_PENDING_CHARS
  set PHONE_EXPORT_NEXT_INDEX = PHONE_EXPORT_PENDING_INDEX + 1
  set PHONE_EXPORT_IS_SAVING = false
  call WebViewer1.RunJavaScript:
    join("window.VSPIMUPhoneIMU.ackExportChunk(\"",
         PHONE_EXPORT_PENDING_ID, "\",",
         PHONE_EXPORT_PENDING_INDEX, ");")

This event is the acknowledgement: do not ask JavaScript for the next chunk until the
file component reports the previous write has completed. That keeps each CSV intact.

8B. FILE ERROR HANDLING
-----------------------
If the File component exposes ErrorOccurred in your AI2 version, handle it by:
  set global PHONE_EXPORT_IS_SAVING = false
  call WebViewer1.RunJavaScript:
    join("window.VSPIMUPhoneIMU.ackExportComplete(\"",
         PHONE_EXPORT_ID, "\",false,\"file component error\");")
  set LabelStatus.Text = "Data export failed; original session remains in memory."

If your File version does not expose ErrorOccurred, wrap this with the Screen.ErrorOccurred
event and check the component/function that triggered the failure before acknowledging.
Never acknowledge a failed write as success.

10. SCREEN INITIALIZATION / BACK BUTTON
----------------------------------------
Screen1.Initialize:
  queue = empty list
  PHONE_CAPTURE_REQUESTED = false
  PHONE_CAPTURE_ENABLED = false
  PHONE_IMU_DROPPED_ROWS = 0
  PHONE_IMU_DROPPED_ROWS_REPORTED = 0
  ClockPhoneFlush.TimerEnabled = false
  AccelerometerSensor1.Enabled = false
  GyroscopeSensor1.Enabled = false
  Keep the existing BLE/WebViewer setup. Do not claim a fixed sensor ODR from these
  components; rates are estimated after the session from sample timestamps/callbacks.

Screen1.BackPressed:
  if PHONE_CAPTURE_ENABLED:
    call FlushPhoneIMUQueue
    set ClockPhoneFlush.TimerEnabled = false
    set PHONE_CAPTURE_ENABLED = false
    set AccelerometerSensor1.Enabled = false
    set GyroscopeSensor1.Enabled = false
  If the existing app is recording, call its normal STOP procedure rather than exit with
  an apparently complete session. Do not claim the sensors continue in the background.

The foreground workflow is the supported first step. App Inventor does not expose a
portable, reliable substitute for a native Android foreground-service lifecycle here.
If the app is backgrounded or the screen is turned off, a sampling gap may occur; quality
checks must remain visible. Do not advertise all-day continuous monitoring.

11. BLE DISCONNECT / RECONNECT
------------------------------
Keep current BLE disconnect handling. If a raw stream disconnect occurs mid-session,
mark/stop that assessment and start a new session after reconnecting rather than splicing
sequences that reset to zero into one clean record. The quality/export layer will flag
sequence discontinuities it receives; it cannot reconstruct samples never received.
