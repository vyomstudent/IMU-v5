# VSPIMU dual-IMU metric catalog and interpretation rules

Algorithm/module id: `VSPIMU-phone-shank-summary-6.0.0`  
This catalog documents the implemented add-on metrics, not clinical validation.

## Implemented features

| Feature | Data / formula | Unit | Minimum data / QC | Interpretation and limitations |
|---|---|---|---|---|
| Shank raw sample count | Rows mirrored from existing `receiveShortsCsv` | samples | Any parsed row; high-confidence summary needs ≥100 | Count received by WebView, not proof all samples generated by the sensor arrived |
| Shank sequence continuity | `100 × received rows / sequence slots from first to last` | % | One or more valid sequence rows | Detects observed gaps but cannot distinguish sensor-read misses from lost BLE notifications |
| Shank sequence gap slots | Difference between consecutive unwrapped sequences minus one | samples | ≥2 sequence rows | Missing sequence slots are not interpolated |
| Shank near-limit rows | Any of six raw int16 axes with absolute value ≥32760 | rows | Any valid row | Near-full-scale proxy only; not a complete analog saturation diagnosis |
| Shank accel centered-vector RMS | `sqrt(var(ax)+var(ay)+var(az))` after raw→m/s² conversion; population variance per axis | m/s² | ≥2 finite rows; quality label requires ≥100 | Within-window movement variability after axis means are removed; not speed, position, pelvis movement or clearance |
| Shank gyro centered-vector RMS | `sqrt(var(gx)+var(gy)+var(gz))` after raw→deg/s conversion | deg/s | ≥2 finite rows; quality label requires ≥100 | Sensor-frame angular-rate variability; not anatomical joint angle |
| Phone acceleration axes | Native AI2 AccelerationChanged x/y/z | m/s² | Each valid callback | Device-frame acceleration components; callback wall timestamp only, no native event timestamp in AI2 callback |
| Phone gyro axes | Native AI2 GyroscopeChanged x/y/z | deg/s | Each valid callback | Device-frame angular rate; gyroscope event timestamp preserved in nanoseconds where provided |
| Phone median observed rate | `1 / median(positive consecutive timestamp intervals)` | Hz | ≥20 timed rows and ≥1s duration for status beyond insufficient | Observed callback rate, not promised sensor ODR. For gyro, native timestamp is used only if complete across that stream |
| Robust interval variability | `1.4826 × MAD(Δt) / median(Δt)` | dimensionless | ≥2 positive intervals; interpreted after ≥20 rows/1s | Timing irregularity feature; sensitive to host callback scheduling and OS batching |
| Long timestamp gaps | Intervals >3× the stream's observed median positive interval | intervals | Rate interval available | Relative gap rule, not known sensor truth. Expected omitted count/percent is a heuristic derived from the observed median interval |
| Duplicate / backwards timestamps | Consecutive equal or decreasing timestamps | counts | Any timed row | Flags clock anomalies; phone acceleration callback time is wall clock and can be adjusted |
| Cross-sensor envelope correlation | Pearson r between 0.5-s binned variability of phone acceleration magnitude and shank gyro magnitude | unitless r | ≥100 phone accel rows, ≥200 shank rows, usable packet-clock fit and ≥8 common bins | Exploratory shared-activity signature, not synchronized gait event agreement; different axes, sites and transfer functions |
| Candidate envelope lag | Best lag among shifts −4.0 to +4.0s in 0.5-s bins, only when best result is distinct, r≥0.35 and ≥10 common bins | seconds | Same as above plus matching threshold | Reported candidate only; never applied to source timestamps. No end-to-end sync uncertainty bound is claimed |
| User annotations | Manual mark at page monotonic time | seconds from page-start | Session active | Context marker only, not a sensor-detected/ground-truth event |
| Existing engine event candidates | Reused `VSPIMU.state()` event arrays when available | seconds/confidence if available | Existing engine must expose events | Kept as estimated candidates; no new event model is trained by the add-on |
| Within-person feature comparison | Current centered RMS compared with prior median and MAD for same profile, pocket, protocol and version | absolute change, %, robust deviation | Eligible current session plus ≥5 prior eligible comparable sessions | Descriptive comparison only. Not an alert, disease detector or causal explanation |

## Quality labels

- `INSUFFICIENT`: fewer than 20 timed samples or less than 1 second of timed span for phone streams; shank summary is insufficient under 100 rows.
- `REVIEW`: at least one detected timestamp gap, duplicate/backwards timestamp, robust interval CV >0.25, shank sequence gap/duplicate, near-limit row, or truncation, as applicable.
- `OBSERVED`: the current checks did not flag those conditions. This is **not** a claim of clinical validity or a guarantee of accuracy.
- `UNAVAILABLE` / `AMBIGUOUS`: insufficient data or no distinct exploratory envelope match; missing values remain missing.
- `METADATA`: user-declared placement and sensor-configuration details, not inferred measurements.

## Per-stream timestamp definitions

| Stream | Preserved time | What it does not mean |
|---|---|---|
| Shank | unsigned sequence, unwrapped sequence, nominal `sequence / 208Hz` relative time, packet receipt `performance.now()` | Shared hardware time or exact IMU acquisition timestamp |
| Phone accelerometer | AI2 `Clock.SystemTime` at callback; page-monotonic estimate computed when batch reaches WebView; batch receipt time | Native Android `SensorEvent.timestamp`; callback delay can perturb time |
| Phone gyroscope | AI2 callback wall time, gyro `SensorEvent.timestamp` in ns when present, WebView receipt time | Cross-device synchronized time; native timestamp only anchors that phone sensor's event clock |

## Features deliberately not implemented

| Requested concept | Status / reason |
|---|---|
| Absolute walking speed or distance | Not estimated. Requires a validated model/reference, known course or additional calibration and drift control. |
| Bilateral asymmetry | Not measured. One distal-tibia IMU does not observe both legs; phone-only alternating peaks do not provide reliable left/right labels. |
| Foot clearance in millimetres / foot drop diagnosis | Not measured. A shank IMU does not directly observe foot-ground distance; integration/orientation drift and attachment motion prevent such a claim. |
| Anatomical ankle/knee/hip angles, torque, power or joint loading | Not calculated. Sensor-frame rate is not anatomical kinematics or force measurement. |
| Definitive FOG episodes / Parkinson's diagnosis / fall-risk prediction | Not added. Requires labelled clinical datasets, external validation and validated thresholds. |
| TUG, sit-to-stand and timed transfers | Not added as protocol. Manual annotations can mark notable moments, but do not constitute validated task segmentation. |
| Infection, dehydration, pain cause, sleep or medication effects, HRV, PPG, temperature | Not inferred. Those data are absent or causation would be unsupported. |
| Phone background / all-day monitoring | Not supported by this foreground-first AI2 integration. Sensor gaps are recorded when callbacks resume; no foreground service was added. |
